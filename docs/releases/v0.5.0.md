# Papliba v0.5.0

Status: Released
Release date: 2026-08-07

## Highlights

- Added a loopback-only ASP.NET Core runner with revisioned SQLite workspace persistence.
- Added frontend hydration, debounced autosave, save status, and persisted workflow edits.
- Added workflow creation, renaming, confirmed deletion, undo, and multi-node marquee deletion.
- Made workflow triggers draggable, removable, and explicitly chosen for new workflows.
- Replaced click-to-connect with live drag-and-drop node connections.
- Added project/workflow-scoped Python script files with recoverable deletion and legacy migration.
- Added Open in support for VS Code, Cursor, Finder, Terminal, Ghostty, and Xcode using their official application icons.
- Added a Codex-powered Python assistant with authentication status, browser sign-in, file preview, and review-first code application.
- Limited newly created agent nodes to Codex and Claude Code while retaining compatibility with existing Python nodes.

## Local data

Workspace state is stored in SQLite under Papliba's operating-system application-data directory. Python files are organized by project, workflow, and node. Set `PAPLIBA_DATA_DIRECTORY` to use a custom development location.

## Validation

The release is validated with:

- the architecture diagram XML check
- an ASP.NET Core runner build
- a production Next.js build
- ESLint and TypeScript checks

## Notes

Papliba v0.5.0 establishes the durable local workflow foundation. Workflow execution remains a frontend demonstration; production execution semantics and richer Codex/Claude agent workspaces are planned for later releases.
